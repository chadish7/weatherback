# AGENTS.md

Notes for AI agents and contributors working on WeatherBack. Keep this file and `README.md`
updated when behaviour, structure, or deployment changes.

## Project

WeatherBack is a small Node.js app that shows the last 7 days of observed weather plus the
forecast in an Apple Weather–style daily list. Data comes from the NOAA NWS API (US only).
It is hosted on a CloudPanel server as a Node.js site run by PM2 behind CloudPanel's nginx.

## Decisions (from the project owner)

- Past window is **7 days** by default (`PAST_DAYS` in `lib/weather.js`). Only highs and lows are needed for the past days.
- A **Load 7 more days** button at the top of the list prepends older days from NCEI, 7 per click, with no limit on how far back.
- Layout is a vertical list of days: past days in full colour, then today, then forecast days **faded**.
- Each row has a temperature range bar with a rain indicator underneath, and there's a hero card for current weather.
- Backend: Node.js with Express. Frontend: **plain JS**, no framework and no build step.
- Zip lookup uses the bundled US Census ZCTA file (`data/zips.json`). No external geocoder.
- °F is the default. °C is a toggle, stored in `localStorage`.

## Layout

| Path | What it is |
| --- | --- |
| `server.js` | Express app: security headers, `/api/zip/:zip`, `/api/weather`, `/api/history`, static files from `public/`. |
| `lib/nws.js` | NWS API client. Sets User-Agent, enforces timeouts, follows observation pagination, caches results. |
| `lib/weather.js` | Builds the API response: picks a station, groups observations into local days, merges in the forecast. |
| `lib/ncei.js` | NCEI Access Data Service client: station search by bounding box, GHCN-Daily TMAX/TMIN/PRCP/SNOW. |
| `lib/history.js` | Builds `/api/history` days in the same shape as past days, picking and gap-filling across nearby stations. |
| `lib/cache.js` | Two-level TTL cache: in memory (also de-duplicates concurrent requests) over SQLite via built-in `node:sqlite`. Also `peek`/`put`/`putMany`/`once` for piece-by-piece caching. |
| `public/` | `index.html`, `styles.css`, `app.js` (ES module), `favicon.svg`. |
| `data/zips.json` | `{ "zip": [lat, lon] }`, generated by `scripts/build-zips.js`. Committed. |
| `ecosystem.config.cjs` | PM2 config for production. `PORT`/`WEATHERBACK_CONTACT` come from the shell at `pm2 start`, so no server-specific edits are committed. |

## Conventions

- ES modules everywhere (`"type": "module"`), except `ecosystem.config.cjs`, which PM2 needs as CommonJS.
- The API always returns **°C and mm**. Unit conversion happens only in `public/app.js`.
- Dates in the API are local `YYYY-MM-DD` strings in the location's time zone. The frontend formats them
  with `timeZone: 'UTC'` at noon to avoid shifting the date.
- Each day has `kind`: `past` | `today` | `forecast`. Past days can have `partial: true`. Days from NCEI have `source: 'ncei'`
  and a `station` id; their high/low are null when no nearby station reported that day.
- In `public/app.js`, `lastData.days` is the `/api/weather` response and `olderDays` holds loaded history. `allDays()` merges them
  and swaps the partial oldest NWS day for its NCEI record. Changing location calls `resetHistory()`, and a token discards
  history responses that arrive after the location has changed.
- The CSP is `'self'` only, with no inline scripts or styles. Build DOM nodes with `createElement`/`textContent`
  and set dynamic styles through `el.style` (CSSOM). Don't use `innerHTML` with data.
- Keep runtime dependencies minimal (currently just `express`). Use Node's built-in `fetch` and `node:sqlite`
  (Node 22.13+; `--disable-warning=ExperimentalWarning` is set in `npm start` and the PM2 config).
- Everything passed through `cached()` must be JSON-serializable, because it's stored in SQLite. Cache plain data and
  build Maps/Sets after reading (see `getDailySummaries`). Cache keys are shared across restarts, so change the key
  prefix if you change a cached value's shape.
- Partial cache hits must fetch only the missing data, never return incomplete results. `cached()` is for
  all-or-nothing values (points, stations, forecast). Data that accumulates uses `peek`/`put`/`putMany`/`once`:
  - NCEI: keys `ncei-day:<station>:<date>`, one per station-day. `null` means NOAA had no record when asked, and it
    expires after 3 h for recent dates. `getDailySummaries` fetches the span of dates missing for any station.
  - NWS: key `obs-store:<station>` = `{ coveredFrom, fetchedAt, observations }`. Refresh is incremental from
    `fetchedAt - 2h` when `coveredFrom <= start`, otherwise a full pull. If the page cap is hit, `coveredFrom` is the
    oldest observation received, so the next call pulls again.
- "Load more" animation: `loadMore()` sets `enteringDates` for one render; `renderDays()` adds `day-enter` and a
  `--enter-delay` stagger to those rows. CSS in `styles.css` (disabled under `prefers-reduced-motion`).
- `lib/nws.js` will only fetch URLs under `https://api.weather.gov/`, and `lib/ncei.js` only under `https://www.ncei.noaa.gov/access/services/`.

## NWS data quirks

- `/stations/{id}/observations` returns at most 500 per page (about 1.5 days at busy airports). Follow
  `pagination.next` until reaching `start`.
- NWS retains only about 7 days of observations, so the oldest past day is usually partial.
- `precipitationLastHour` is null at many stations. Fall back to `presentWeather` (counting hours with rain/snow).
  Several reports in one hour can repeat the accumulation, so take the max per clock hour.
- Some stations (for example KNYC) omit `textDescription` and `icon`. Current conditions fall back to the
  first forecast period.
- Forecast days pair the daytime period (high) with that date's night period (low). Incomplete forecast days are dropped.
- Points outside the US return 404, which the API passes on to the user as a "US only" message.

## NCEI data quirks

- Station search: `GET /access/services/search/v1/data?dataset=daily-summaries&bbox=N,W,S,E&startDate=&endDate=&dataTypes=TMAX,TMIN`.
  Each result's `stations[0].dataTypes[].endDate` tells you whether that station still reports a type.
- Data: `GET /access/services/data/v1?dataset=daily-summaries&stations=A,B&startDate=&endDate=&units=metric&format=json`.
  Values come back as strings, and missing types are omitted from the row.
- GHCN-Daily lags about 3 days, and some co-op stations lag a week or more. The NCEI station is usually different
  from the NWS station (for example `USW00094728` vs `KNYC`), but values match closely for the same site.
- GHCN-Daily has no cloud cover. Icons come from PRCP/SNOW and weather-type flags (`WT01`/`WT02` fog, `WT03` thunder,
  `WT05` hail, `WT08` haze, `WT11` high wind, `WT16` rain, `WT18` snow). A flag's key is only present on days it occurred.
  Days with none of these get category `dry` (🌤️). Don't claim "sunny" for them.
- The `global-hourly` (ISD) dataset returned no rows through the Access Data Service when tested (Oct 2026), so it isn't used for sky cover.

## Checking changes

There's no test suite yet. To check by hand:

```bash
npm start
curl -s 'localhost:3000/api/weather?lat=39.7515&lon=-104.9977' | head -c 600
curl -s localhost:3000/api/zip/10001
curl -s 'localhost:3000/api/history?lat=40.7506&lon=-73.9973&end=2026-10-06&days=7'
```

Then load `http://localhost:3000` in a browser (geolocation works on localhost) and try a zip code,
the unit toggle, and Load more.
